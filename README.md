# Naslai — бэкенд на Django REST Framework

Полный бэкенд сервиса: аккаунты, токены, генерация карточек, промокоды,
админ-панель и разбор карточек «Плохие продажи?».

---

## Запуск за пять минут

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env          # заполнить ключи

python manage.py migrate
python manage.py createsuperuser
DJANGO_DEBUG=1 python manage.py runserver 127.0.0.1:8787
```

`DJANGO_DEBUG=1` для локальной работы нужен явно: по умолчанию отладка
ВЫКЛЮЧЕНА. Так забытая переменная на боевом сервере не превращается в
страницу ошибки с ключами наружу.

`.env` подхватывается сам (`config/settings.py`, `load_env_file`) —
экспортировать переменные вручную не нужно. Файл в `.gitignore`: в
репозиторий он не попадёт, и не должен.

**Уже заданная переменная окружения сильнее файла.** На сервере значения
выставляет systemd, и забытый рядом с кодом `.env` разработчика не должен
молча подменить боевые настройки.

Путь можно перенести: `NASLAI_ENV_FILE=/etc/naslai/naslai.env`.

Порт 8787 не случайный: фронтенд проксирует `/api` и `/media` именно туда
(`vite.config.ts`). Возьмёте другой — поправьте и там.

**Первый запуск делайте с `GENERATION_PROVIDER=mock`.** Тогда сервер
рисует заглушку вместо картинки и не тратит ни цента. Убедитесь, что
регистрация и списание токенов работают, и только потом включайте `openai`.
Иначе будете искать причину поломки сразу в двух местах.

## Локальная разработка: какие адреса разрешены

Фронтенд запускается на **http://127.0.0.1:5173** (`npm run dev:web` в
папке `front-nasl`). Vite проксирует `/api` и `/media` на Django, поэтому
для браузера всё выглядит одним адресом — ни CORS, ни cookie проблем не
создают. Это ровно та же схема, что и на боевом сервере.

В список разрешённых источников при `DJANGO_DEBUG=1` входят:

```
http://127.0.0.1:5173   http://localhost:5173     (vite dev)
http://127.0.0.1:5174   http://localhost:5174     (второй экземпляр)
http://127.0.0.1:4173   http://localhost:4173     (vite preview)
http://127.0.0.1:4174   http://localhost:4174
```

При `DJANGO_DEBUG=0` локальные адреса из списка ПРОПАДАЮТ. Остаются
только `https://naslai.uz` и `https://www.naslai.uz`.

## Очередь генерации

Одна картинка у OpenAI рисуется до трёх минут, пакет из пяти — до
пятнадцати. Пока это выполнялось прямо в HTTP-запросе, рабочий процесс
gunicorn был занят всё это время: трёх одновременных генераций хватало,
чтобы сайт перестал отвечать остальным.

Теперь задача уходит в Celery, а фронтенд опрашивает
`GET /api/generations/<id>` — он делал это и раньше, договор не менялся.
Заодно по-настоящему заработала отмена: флаг `cancelled` читается между
картинками, и раньше запрос просто не успевал прийти.

**Без `CELERY_BROKER_URL` генерация выполняется прямо в запросе.** Это не
заглушка, а рабочий режим для двух случаев: локальной разработки под
Windows (там нет ни Redis, ни нормального воркера Celery) и тестов,
которым нужен готовый результат сразу после запроса. На боевом сервере
переменную заполняют.

```bash
CELERY_BROKER_URL=redis://127.0.0.1:6379/0
celery -A config worker --loglevel=info --concurrency=2
```

Три решения, которые стоит понимать до правок:

**Повторов нет.** Каждый повтор — ещё один платный вызов провайдера за
одну оплаченную генерацию. Упавшая задача возвращает токены, человек
решает сам, пробовать ли снова.

**Задача подтверждается сразу, до выполнения** (`CELERY_TASK_ACKS_LATE =
False`). Обратный вариант выглядит надёжнее, но упавший воркер вернул бы
задачу в очередь, и мы заплатили бы провайдеру дважды. Дополнительно сама
задача отказывается работать, если её статус уже не `queued`.

**Зависшие задачи подбирает отдельная команда.** Это плата за предыдущий
пункт: если воркер умрёт посреди работы, задача останется в `processing`
навсегда — человек списал токены и не получил ничего. Раз в 15 минут по
таймеру:

```bash
python manage.py release_stuck_jobs
```

Она переводит такие задачи в `failed` и возвращает токены. Порог —
`STUCK_JOB_MINUTES`, по умолчанию 30 минут; он должен быть заметно больше
самой долгой честной генерации.

**Если Redis недоступен** в момент постановки в очередь, токены
возвращаются сразу же, а фронтенд получает 503 с понятным текстом. Списать
и промолчать — худшее, что здесь можно сделать.

## Экономика

Цены **не забиты константами**. Они считаются от себестоимости картинки:

```
себестоимость → цена токена при максимальной скидке → базовая цена → пакеты
```

Меняется курс доллара или тариф OpenAI — правите одну переменную,
цены пересчитываются, маржа держится. Текущие значения:

| Пакет | Токенов | Цена | За штуку |
|---|---|---|---|
| Start | 10 | 39 000 сум | 3 900 |
| Plus | 40 | 139 500 сум | 3 488 |
| Pro | 120 | 381 000 сум | 3 175 |
| Studio | 500 | 1 451 000 сум | 2 902 |

Эти числа совпадают с Node-версией до сума — есть тест
`billing.tests.PricingTests.test_packs_match_node_version`, он упадёт при
расхождении.

**Одна картинка — один токен.** Одинаково для всех режимов, поэтому маржа
везде совпадает и её не нужно считать под каждую операцию отдельно.

## Решения, которые выглядят странно, но так задумано

**Бесплатные токены только подтверждённым.** Регистрация по почте даёт
`STARTER_TOKENS_UNVERIFIED` = 0. Google и Telegram привязаны к телефону,
им даём `STARTER_TOKENS` = 2. Одноразовый ящик делается за десять секунд,
и именно через него накручивали бесплатные генерации.

**Проверка MX при регистрации.** `dkemqmdq@dmwdqw.uz` проходит любую
регулярку. У живого почтового домена есть MX-запись, у выдуманного нет.
При сбое DNS пропускаем: блокировать живого человека из-за наших проблем
хуже, чем пустить сомнительный адрес.

**Админка отвечает 404, а не 403.** Посторонний не должен даже узнать,
что раздел существует. Пустой `ADMIN_EMAILS` = админка закрыта для всех.

**Использованный промокод не удаляется, а выключается.** На нём держится
статистика блогера: сколько людей он привёл.

**При провале генерации токены возвращаются.** Человек заплатил и не
получил картинку — сгоревшие токены выглядят как обман.

**Отмена возвращает токены только за неотрисованные картинки.** За готовые
мы уже заплатили OpenAI, и человек их получает. Прервать запрос, который
уже ушёл провайдеру, нельзя, поэтому флаг `cancelled` проверяется между
картинками.

**Картинка сжимается ровно один раз.** Модель отдаёт PNG без потерь,
дальше обрезка 1088→1080 пиксель в пиксель и одно сжатие в JPEG. Двойное
сжатие оставляет грязные ореолы вокруг букв — это уже ловили на реальных
карточках.

**Ссылка на товар в аудите не обязательна.** Страница Uzum рисуется
скриптом, её внутренний JSON могут закрыть в любой момент. Не получилось —
отчёт строится по картинкам и ответам продавца.

### Как авторизуется браузер

Cookie сессии, а не токен в localStorage. Cookie помечена `HttpOnly`:
чужой скрипт на странице её не прочитает, тогда как значение из
localStorage читается одной строчкой.

Плата за это — CSRF. Django требует заголовок `X-CSRFToken` на каждом
POST/PATCH/DELETE. Фронтенд берёт значение из cookie `csrftoken` (её
ставит `GET /api/auth/session`) и подставляет сам — см.
`src/app/apiClient.ts`. Пишете свой запрос мимо `apiFetch` — получите 403
и будете долго искать причину.

Для обращений из своего кода остался токен DRF: `Authorization: Token
<ключ>`. Он приходит в ответе на вход и на регистрацию.

## Безопасность

Настроено в `config/settings.py`, раздел за разделом:

| Что | Как |
|---|---|
| Чужой домен в браузере | `CORS_ALLOW_ALL_ORIGINS = False` всегда. Список: `naslai.uz`, `www.naslai.uz` и — только при DEBUG — локальные порты Vite |
| Чужой заголовок Host | `ALLOWED_HOSTS` по именам, всё остальное — 400 |
| Подделка запроса (CSRF) | Проверка `X-CSRFToken` + `CSRF_TRUSTED_ORIGINS` |
| Кража сессии через XSS | `SESSION_COOKIE_HTTPONLY = True` |
| Перехват на канале | `SESSION_COOKIE_SECURE` / `CSRF_COOKIE_SECURE` при DEBUG=0, HSTS на год |
| Подмена кликов | `X_FRAME_OPTIONS = DENY` |
| Подбор пароля, накрутка | Ограничение частоты по видам операций (`config/throttling.py`) |
| Разведка структуры API | Просматриваемое HTML-API выключено при DEBUG=0 |
| Перебор адреса админки | `DJANGO_ADMIN_PATH` |
| Запрос на сотни мегабайт | `DATA_UPLOAD_MAX_MEMORY_SIZE` |
| Чужие адреса в разборе карточки | Принимаем только `data:image/...`, иначе наш ключ OpenAI станет чужим загрузчиком страниц |
| Утечка ключей через страницу ошибки | `DEBUG` по умолчанию 0, `SECRET_KEY` обязателен |

Проверить перед выкладкой:

```bash
python manage.py check --deploy
```

Отдельно: `ADMIN_EMAILS` пустой = админка закрыта для всех. Это и есть
безопасное значение по умолчанию.

## Чего ещё нет

- **Платежи Click и Payme.** Заказ можно создать, но токены должны
  начисляться только после подтверждения провайдера — этого кода нет.
  Не начисляйте токены до webhook, даже «на время теста».
- **Генерация видео.** Поставщика нет, коэффициенты в `pricing.py`
  временные.
- **Реферальная программа.** Кабинет её показывает, но начислений нет —
  возвращаются нули.
- **Сохранение оценок результата.** Фронтенд показывает звёзды, но никуда
  их не отправляет.

## Перед боевым запуском

1. `DJANGO_SECRET_KEY` — настоящий. Без него сервер не стартует.
2. `DJANGO_DEBUG` не трогать (по умолчанию 0).
3. `DJANGO_ALLOWED_HOSTS=naslai.uz,www.naslai.uz`.
4. `NASLAI_SITE_DOMAIN=naslai.uz` — отсюда считаются CORS и CSRF.
5. `ADMIN_EMAILS` — ваша почта, иначе админка закрыта.
6. SQLite заменить на PostgreSQL: при нескольких процессах SQLite
   блокируется на запись.
7. `NASLAI_DB_PATH` и `NASLAI_MEDIA_ROOT` — вне папки с кодом, иначе
   выкладка новой версии затрёт данные.
8. `python manage.py collectstatic` — иначе админка будет без стилей.
9. `CELERY_BROKER_URL` — заполнить, иначе генерация снова займёт процессы
   gunicorn.
10. Воркер Celery и таймер `release_stuck_jobs` — см. `DEPLOY.md`.
11. `python manage.py check --deploy` — прочитать все предупреждения.

### Переменные на сервере

Два способа, оба рабочие:

**1. Файл `.env` рядом с кодом.** Просто, но лежит в папке, которую
перезаписывает выкладка, и читается тем же пользователем, что и код.

**2. Отдельный файл для systemd — так лучше.** Он вне папки с кодом,
принадлежит root и читается только сервисом:

```bash
sudo install -d -m 750 /etc/naslai
sudo install -m 640 -o root -g naslai /dev/null /etc/naslai/naslai.env
sudo nano /etc/naslai/naslai.env          # заполнить по .env.example
```

Сам сервис:

```ini
# /etc/systemd/system/naslai.service
[Unit]
Description=Naslai backend
After=network.target

[Service]
User=naslai
Group=naslai
WorkingDirectory=/srv/naslai
EnvironmentFile=/etc/naslai/naslai.env
ExecStart=/srv/naslai/.venv/bin/gunicorn config.wsgi:application \
          --bind 127.0.0.1:8787 --workers 3 --timeout 300
Restart=always
RestartSec=5

# Реальная генерация держится до трёх минут — таймаут не занижайте,
# иначе systemd убьёт процесс посреди оплаченного запроса.

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now naslai
```

`gunicorn` в `requirements.txt` намеренно нет: под Windows он не ставится
и ломает локальную установку. На сервере: `pip install gunicorn`.

**`manage.py runserver` на боевом сервере не использовать.** Он
однопоточный, без ограничений и прямо предупреждает об этом сам.

### Схема развёртывания

Сайт и API на ОДНОМ домене — так проще и безопаснее: cookie не уезжает
между поддоменами, ссылки на картинки остаются относительными, а кнопка
«скачать» работает (у ссылки на чужой домен браузер игнорирует атрибут
`download`).

```nginx
server {
    listen 443 ssl http2;
    server_name naslai.uz www.naslai.uz;

    # Собранный фронтенд: npm run build -> папка dist
    root /var/www/naslai/dist;
    index index.html;

    # Все прочие адреса отдаёт SPA
    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8787;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        # Без этого Django считает соединение незашифрованным и не
        # ставит Secure на cookie.
        proxy_set_header X-Forwarded-Proto $scheme;
        # Фото уходят строкой base64 внутри JSON.
        client_max_body_size 25m;
        # Реальная генерация держится до трёх минут.
        proxy_read_timeout 300s;
    }

    location /media/ { alias /var/lib/naslai/media/; expires 30d; }
    location /static/ { alias /var/lib/naslai/static/; expires 30d; }
}

server {
    listen 80;
    server_name naslai.uz www.naslai.uz;
    return 301 https://$host$request_uri;
}
```

Если API всё-таки вынесете на `api.naslai.uz` — задайте
`DJANGO_COOKIE_DOMAIN=.naslai.uz` и `NASLAI_ABSOLUTE_MEDIA_URLS=1`.
